## Question

自动快照与时间点还原的设计：快照粒度（按键还是按操作）与格式（.reg 还是内部结构）；存储位置与保留策略（绿色便携单 exe 约束下数据放哪）；还原时的冲突处理（快照之后系统已变化怎么办）；快照与条目操作的自动关联方式（每次禁用/删除前自动留档）。产出后与用户确认，写清还原的用户流程。

调用 "grilling" 与 "domain-modeling"。

## Resolution

四项决策全部定案（用户逐项确认），技术底座沿用「Tauri 栈系统层能力调研」结论（JSON 主存储 + reg.exe .reg 兜底 + API 精确写回）：

**B1 粒度与格式 —— 每操作一录，全带前像。** 每次条目操作（禁用/启用/删除/新增/编辑）自动生成一条快照记录：时间、操作类型、涉及条目、受影响键的**改动前完整状态**（JSON 主存储，单条几 KB 量级）；删除类记录额外导出 .reg 作人工恢复交付物；另设「手动快照」按钮拍当前全部受管键的全量点。历史中每条记录都可一键还原，体验一致。

**B2 存储与保留 —— 便携优先 + 软上限。** 数据放 exe 同目录 `data\snapshots\`（数据随程序走）；目录不可写时回退 `%APPDATA%\RightClickManager\snapshots\`。自动记录滚动保留最近 60 条；**删除类快照与手动快照点永不自动清理**；设置页可手动清空历史（清空前提示）。

**B3 还原冲突 —— 还原可撤销 + 如实报告。** 还原是权威操作：逐键精确写回（不走 reg import 的 merge 语义），一律按快照覆盖；写回前自动拍一张「还原前快照」，还原本身随时可撤销；对「当前值与快照后像不符」（期间被外部改动）的键，完成后在结果页如实列出并指明可退回。

**B4 还原粒度 —— v1 只整条还原。** 一条记录一次还原，不做键级挑选。

**还原用户流程（定稿）**：快照历史 → 选时间点「还原至此」→ 确认 → 自动拍还原前快照 → 逐键写回 → 结果页（N 键写回 · M 键期间被外部改过已按快照覆盖 · 「撤销本次还原」按钮）→ 提示重启资源管理器后生效（重启引导的统一策略归「异常与边界处理」工单）。
