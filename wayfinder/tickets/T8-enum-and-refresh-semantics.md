## Question

「核心域模型与操作语义」定案后可切：何时扫描注册表与打包清单（启动即扫 / 首次进入扫 / 手动刷新）；扫描期间列表的呈现（骨架/进度）；外部变化（安装/卸载软件）后条目何时过期；刷新按钮与自动重扫的取舍；大注册表量下的性能底线（可接受的首屏时间）。与用户敲定后记录进工单。

调用 "grilling" 与 "domain-modeling"。

## Resolution

四项决策全部定案（用户逐项确认）：

1. **扫描时机**：启动即扫 + 手动「重新扫描」兜底；不做启动缓存体系（若将来需要，待快照存储落地后另立工单）。
2. **扫描呈现**：首次扫描 = 骨架屏（灰砖占位 + 微光，内容形状先行）；重扫 = **保留旧列表** + 按钮内转圈，不清屏不闪跳。
3. **外部变化感知**：窗口获得焦点时**静默重扫**（差异就地更新，不打扰），配合手动按钮；不做注册表实时监听（RegNotify 易误触发、收益低）。
4. **性能底线**：首屏（含图标提取）目标 ≤ 1 秒；当前内联提取实测达标则不提前优化；若实测超标，再把图标改为异步渐进填充（两阶段：先出列表、图标后台补齐）。验证方式：`tauri dev` 实测启动到列表可交互的时间。
